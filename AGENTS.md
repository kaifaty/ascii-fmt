# AI Developer Guide for ascii-fmt

## Purpose

This document provides AI agents with information needed to develop, maintain, and extend the `ascii-fmt` package. It assumes you are an AI assistant working on this Rust project and need context about architecture, patterns, and development workflow.

## Project Overview

### What is ascii-fmt?

`ascii-fmt` is a CLI tool written in Rust that automatically fixes and aligns ASCII diagrams, particularly those generated by AI agents.

**Core Problem**: AI agents struggle with ASCII diagram formatting due to:
- Tokenization issues with box-drawing characters
- Character width variations (Unicode)
- Lack of visual feedback
- Context window limitations

**Solution**: Post-processing tool that detects patterns and fixes common formatting errors.

### Key Goals

1. **Performance**: <10ms for diagrams up to 1000x1000 characters, O(n) complexity
2. **Quality**: >80% test coverage, zero `unsafe` code, zero clippy warnings
3. **Usability**: Simple CLI, supports multiple diagram types, configurable styles

## Core Architecture

### Two-Pass Algorithm

The formatter uses a two-pass approach:

**Phase 1: Analysis (Read-Only)**
1. Parse input into `ParsedDiagram`
2. Detect diagram type via `patterns::detect_type()`
3. Analyze grid structure via `grid::analyze_grid()`

**Phase 2: Transformation (Apply Changes)**
4. Clone diagram (preserve original)
5. Apply fixes in-place:
   - `box_drawing::fix_box_drawing_symbols()`
   - `grid::normalize_whitespace()`
   - `text_align::align_text_content()`
6. Render to final string

### Key Data Structures

```rust
// Parsed diagram representation
pub struct ParsedDiagram {
    pub lines: Vec<String>,          // Original lines
    pub diagram_type: DiagramType,   // Detected type
}

// Grid metrics for alignment
pub struct GridMetrics {
    pub column_width: usize,         // Detected cell width
    pub row_height: usize,          // Usually 1
    pub columns: Vec<usize>,        // X positions of grid lines
    pub rows: Vec<usize>,           // Y positions of grid lines
}

// Formatting options
pub struct Options {
    pub width: usize,               // Target grid cell width
    pub style: Style,               // Minimal/Standard/Detailed
    pub fix_box_drawing: bool,      // Fix +,-,| → Unicode
    pub fix_whitespace: bool,       // Normalize spaces
    pub preserve_empty_lines: bool,  // Keep empty lines
    pub dry_run: bool,             // Preview mode
    pub verbose: bool,              // Debug output
}
```

### Module Responsibilities

| Module | Responsibility | Key Functions |
|--------|---------------|--------------|
| `parser.rs` | Parse input to AST | `parse()` → `ParsedDiagram` |
| `patterns.rs` | Detect diagram type | `detect_type()` → `DiagramType` |
| `grid.rs` | Analyze structure | `analyze_grid()` → `GridMetrics`, `normalize_whitespace()` |
| `box_drawing.rs` | Fix ASCII symbols | `fix_box_drawing_symbols()` |
| `text_align.rs` | Align text content | `align_text_content()` |
| `formatter.rs` | Orchestrate workflow | `format_ascii()` → `String` |
| `cli.rs` | Parse CLI args | `Cli::parse()` → `Options` |
| `utils.rs` | Utility functions | Character checks, `most_common()`, `align_to_grid()` |
| `error.rs` | Error types | `Error` enum via `thiserror` |

## Development Patterns

### Adding New Diagram Types

To support a new diagram type:

1. **Add variant to `DiagramType` enum** (`patterns.rs`):
```rust
pub enum DiagramType {
    Flowchart,
    Tree,
    Architecture,
    Sequence,
    Table,
    Network,        // New type
    Unknown,
}
```

2. **Add detection logic** in `patterns::detect_type()`:
```rust

    // ... existing checks ...

    // Add new detection logic
    let has_network_symbols = lines.iter().any(|l| l.contains("┈") || l.contains("╋"));

    if has_network_symbols && !has_all_corners {
        return DiagramType::Network;
    }

    // ... rest of function ...
}
```

3. **Add tests** to `patterns.rs`:
```rust
#[test]
fn test_detect_type_network() {
    let lines = vec![
        "Node1 ──┬── Node2".to_string(),
        "        │".to_string(),
        "        └── Node3".to_string(),
    ];
    assert_eq!(detect_type(&lines), DiagramType::Network);
}
```

4. **Add fixtures** to `tests/fixtures/network/`:
- `bad.txt` - Example unformatted diagram
- `good.txt` - Expected formatted output

5. **Add integration test** to `tests/integration_test.rs`:
```rust
#[test]
fn test_integration_network_diagram() {
    let input = include_str!("fixtures/network/bad.txt");
    let expected = include_str!("fixtures/network/good.txt");
    let output = formatter::format_ascii(input, &options).unwrap();
    assert_eq!(output, expected);
}
```

### Adding New Style Variant

To add a new formatting style:

1. **Add variant to `Style` enum** (`text_align.rs`):
```rust
pub enum Style {

    Standard,
    Detailed,

2. **Implement style-specific logic** in `align_text_content()`:
```rust
pub fn align_text_content(
    diagram: &mut ParsedDiagram,
    _metrics: &GridMetrics,
    style: Style,
) -> Result<()> {
    for line in &mut diagram.lines {
        if is_text_line(line) {
            *line = align_text_in_line(line, style);
        }
    }
    Ok(())
}

        return String::new();

    if original_len <= text_len {
        return line.to_string();

        Style::Standard => /* ... */,
        Style::Detailed => center_text(trimmed, original_len),
        Style::Compact => /* new implementation */,

}
```

**Unit test coverage requirements**:

- Test with `cargo test <module>`

### Integration Tests

Full workflow tests in `tests/integration_test.rs`:

```rust
#[test]
fn test_integration_full_workflow() {
    let input = "+---+\n| A |\n+---+";
    let options = Options::default();

    let result = formatter::format_ascii(input, &options);

**Integration test requirements**:

## Code Style and Quality Standards

### Formatting

Use `rustfmt`:
```bash
cargo fmt
```

### Linting

Use `clippy` with strict settings:
```bash
cargo clippy -- -D warnings
```

### Forbidden Patterns

**Never** use:
- `unwrap()` - use `?` for error propagation
- `expect()` - use `?` in production code
- Empty catch blocks: `catch(e) {}`
- `unsafe` - project goal is zero `unsafe` code

**Always** use:
- `?` for error propagation
- Descriptive error messages via `thiserror`
- `Result<T>` return types for fallible operations

### Documentation

**Public functions** must have doc comments:
```rust
/// Parses ASCII diagram into AST.

/// # Arguments

## Performance Guidelines

### Memory Management

**Good - Pre-allocate capacity:**
```rust
let mut result = String::with_capacity(estimated_size);
for line in lines {
    result.push_str(process(line));
}
```

**Bad - Repeated allocation:**
```rust
let mut result = String::new();
for line in lines {
    result = process(line);  // Reallocates each time
}
```

### Unicode Width

**Good - Cache width calculation:**
```rust
let width = UnicodeWidthStr::width(text);
for i in 0..100 {
    use_cached_width(width);
}
```

**Bad - Recalculate repeatedly:**
```rust
for i in 0..100 {
    let width = UnicodeWidthStr::width(text);  // Expensive Unicode calc
}
```

### Algorithm Complexity

- **Target**: O(n) where n = number of characters
- **Avoid**: Nested loops when possible
- **Use**: HashMap for lookups, not linear search

## Troubleshooting Common Issues

### Issue: Tests Failing on Unicode

**Symptoms**: Tests pass locally but fail in CI

**Cause**: Locale differences, Unicode handling

**Solution**: Ensure UTF-8 environment:
```rust
// Use std::str for UTF-8 validation
let text = String::from_utf8(bytes)?;
```

### Issue: Clippy Warnings

**Symptoms**: CI fails with clippy warnings

**Solution**: Fix warnings or allow with justification:
```rust
#[allow(clippy::too_many_arguments)]  // Justify why needed
fn complex_function(a: u8, b: u8, c: u8, /* ... */) { }
```

### Issue: Performance Regression

**Symptoms**: Benchmarks slower after change

**Solution**: Profile with:
```bash
cargo flamegraph --bin ascii-fmt
```
